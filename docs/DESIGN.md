# Pearlie: design

Status: draft, agreed in chat on 2026-11-08 (DocuTeach planner session). Nothing is built yet.

## 1. What it is

Pearlie is a self-hosted media hub. From one mobile-first web app you:

- browse your **own library**: Stash images, Stash videos, Komga series and books (with a reader);
- browse **external sites**: Danbooru, Gelbooru, Rule34, nhentai;
- **save** from those sites into Stash (images) or Komga (galleries as CBZ), already tagged, with no duplicates;
- **filter** what you see and what you save with your own tag rules.

The web app comes first (self-hosted, then PWA). A native iOS client (SwiftUI) follows later on the same API.

## 2. Product rules (every change is checked against these)

1. **Stash and Komga are the library.** Pearlie stores only its own data: jobs, rules, the index of saved items (source, post id, MD5), trash records. It never keeps a second copy of the media, except a disposable, size-capped thumbnail cache, thumbnails only, never full media, stored in Pearlie's data folder, not under trash/undo. 
2. **Never exposed directly.** Access only through Tailscale/WireGuard or a reverse proxy with login. Outbound calls go only to the configured sites (including their `/favicon.ico` for the Discover site icons, except nhentai whose icon is a static file in the repo, and their thumbnail CDN hosts, fetched through the thumbnail cache), Stash and Komga, and to GitHub (`api.github.com` for the update check, `codeload.github.com` for the update download; no tokens; can be turned off).
3. **Secrets stay local.** API keys and site cookies live in `.env` or the local config, are never logged and never reach the browser. Clients never get Stash or Komga keys. Secrets may be typed into the Options page (write-only, stored encrypted); they are never shown, logged or sent to the browser.
4. **No delete without undo.** Library deletes go to a Pearlie trash folder with an Undo toast; real deletion happens after a retention period the user sets.
5. **Polite to sites.** Save jobs: every source has a throttle; one download at a time per site by default. Browsing streams (user decision 2026-11-14, `/api/media/web/...` preview, full and page images): faster than a browser by default. The setting `images_per_site` (Options, default 10, range 1-16) sets the parallel images per site; the nhentai page slots are part of it and never exceed it. On 403/429/503 the site pauses (Retry-After is honoured), falls back to the browser level (6), goes lower only if errors continue, then recovers slowly to the setting. A thumbnail that fails with 429/503 (like 404/502) is remembered for 60 s per post: the proxy answers at once with no site call, then tries once more. Each stream has a time limit (300 s, video 1800 s). API calls keep the 2 s pace.
6. **Thin clients.** All logic lives in the backend. The web UI and the iOS app only call the JSON API. The safe-mode filter and the reject-list edit run in the backend; the client sends `safe` and shows the result.
7. **UI:** no clutter, icons over text in tight bars, touch targets at least 44 px.

## 3. Stack

| Part | Choice | Why |
|---|---|---|
| Backend | Python 3.12+, FastAPI, httpx, SQLite | gallery-dl is a Python library we can call in-process |
| Downloads | gallery-dl (moved to Codeberg) plus httpx | gallery-dl covers nhentai; boorus use their JSON APIs directly |
| Frontend | Svelte + Vite single-page app, built to static files and served by FastAPI | small and fast on a phone; an SPA keeps the video player alive between screens |
| Deploy | Debian LXC on Proxmox (community-scripts installer), Pearlie in a venv under systemd, OMV share bind-mounted from the host | files owned by the Stash/Komga UID/GID (OMV all_squash) |
| iOS (later) | SwiftUI, AVKit for video and PiP | same JSON API, token login |

## 4. Architecture

```
phone / browser ──► Pearlie (FastAPI + static Svelte UI)
                     ├── sources/   Danbooru, Gelbooru/Rule34, nhentai  ──► the sites
                     ├── targets/   Stash (GraphQL), Komga (REST)        ──► your servers
                     ├── filters/   base list + user rules
                     ├── jobs/      SQLite queue + one worker, per-site throttle
                     └── proxy/     thumbnails, images, video (HTTP Range), book pages
NFS share (OMV): .../stash-library/stash-incoming   .../komga-library/komga-incoming   .../pearlie-trash
```

Pearlie creates `PEARLIE_TRASH_DIR` at start and again before a trash move; if it cannot, trash answers 503 `trash_unavailable` and the Library shows "Trash folder not available".

Pearlie triggers Stash and Komga scans itself after each save, because file watching over NFS is unreliable.

**Logs.** `backend/app/logs.py` writes one file per local day, `pearlie-YYYY-MM-DD.log`, into `PEARLIE_LOG_DIR` (default: a `logs` folder next to the database). One record is one line (`key=value` fields; newlines escaped). A file stops at 20 MB (errors still get through); files older than 7 days (`PEARLIE_LOG_KEEP_DAYS`) are deleted at start-up and at each day change. A scrub filter removes every registered secret (env keys, keys saved on the Options page, site cookies) and common secret shapes (`api_key=`, `Authorization`, cookies) from the final line, tracebacks included. `PEARLIE_LOG_DEBUG=1` (or the stored `logs.debug` setting) adds debug lines. The save pipeline logs each step with the job and post id; a failed Stash lookup also logs file-on-disk, Stash library paths and a checksum search elsewhere, and the worker end line carries state, code and message. Outbound HTTP (sites, Stash, Komga, the update check and download) is logged through httpx hooks (`install_http_hooks`): method, host, status and time, with the URL scrubbed. The per-site throttle logs its waits at debug and a backoff (status, `Retry-After`, wait) as a warning.

## 7. Targets

### Stash (POST `/graphql`, header `ApiKey: <key>`)

Save flow for one image:
1. Dedupe: Pearlie's own `saved_items` table, then `findImages(image_filter: { checksum: { value: $md5, modifier: EQUALS } })`. A `saved_items` hit with an image id is checked once with `findImage(id)`; if Stash no longer has it (deleted there), the stale row is dropped and the save goes on. A Stash error keeps the row. This applies to `/api/save` (409) and to the worker; no bulk reconcile. An item in the Pearlie trash is not stale: its row stays, and `/api/save` answers 409 with code `in_trash` (extra `in_trash` true and the trash `token`, so the UI can offer Restore); the worker reports the post as a duplicate ("in trash").
2. Write the file into `stash-incoming`.
3. `metadataScan(input: { paths: [$path] })` returns a job id; poll `findJob(input: { id })` until done.
4. `findImages(image_filter: { path: { value: $path, modifier: EQUALS } })` gives the new image id.
5. Per tag: `findTags(tag_filter: { name: { value, modifier: EQUALS } })`, else `tagCreate(input: { name })`.
6. `imageUpdate(input: { id, tag_ids, urls: [sourceUrl] })`.

Browsing: `findImages` (`paths { thumbnail image }`), `findScenes` (`paths { screenshot }`, plus `date` and `studio { name }`, names to confirm in the Stash playground), `sceneStreams(id)` for playback. Editing: `imageUpdate` / `sceneUpdate` for rating, favorite and tags.

Video card: video tiles show the poster with a resolution badge (bottom left) and duration (bottom right), then title and a muted "studio - date" line. On mouse hover or a 500 ms touch long-press a muted looping preview plays from `/api/media/stash/scene/{id}/preview`, a proxy of Stash's REST `/scene/{id}/preview` that passes `Range` through (206 with `Content-Range`) and maps an upstream 404 to 404. One preview plays at a time; it stops on leave, release, scroll, unmount or a video error (the poster stays, and that card does not retry until reload, even after a one-off network error; likely: Stash has no generated preview for the scene (unconfirmed)). No preview with reduced motion; with SFW on it plays only on a card the user already revealed.

Library browsing (read-only, `backend/app/targets/stash_client.py`). Check these exact queries in `http://<stash>/playground` before a live test:
- Images: `query($f: FindFilterType) { findImages(filter: $f) { count images { id title rating100 created_at urls tags { name } visual_files { ... on ImageFile { basename width height size } } } } }`, detail `findImage(id: $id)` with the same fields.
- Scenes: `query($f: FindFilterType) { findScenes(filter: $f) { count scenes { id title rating100 created_at urls tags { name } files { basename width height duration video_codec size } } } }`, detail `findScene(id: $id)` plus `sceneStreams { url mime_type label }`.
- `$f` carries `page`, `per_page`, `q`, `sort` (`created_at`, `rating`, `random_<seed>`) and `direction`.
- Media is not fetched from the `paths` fields: the backend proxies `/image/{id}/thumbnail`, `/image/{id}/image`, `/scene/{id}/screenshot`, `/scene/{id}/stream` and `/scene/{id}/{stream.m3u8|stream.mp4|stream.webm|N.ts}` with the key in the `ApiKey` header only. Only a valid `resolution` query value is forwarded, and HLS playlists are rewritten so no Stash URL or key reaches the browser.
- Fallback streams in the item detail come from `sceneStreams`, mapped to proxy URLs; `stash_link` is `<stash_public_url or stash_url>/scenes/{id}` or `/images/{id}`, never with a key.

Notes:
- Stash v0.32.0 (Oct 2026) returns 403 to public IPs when no credentials are set. Give Stash an API key.
- The schema shifts between releases: check every field above in `http://<stash>/playground` before coding, especially whether the image `checksum` filter is MD5.

### Komga (header `X-API-Key: <key>`)

- `GET /api/v1/libraries` at startup: map library to folder path and id.
- After the CBZ lands in `komga-incoming`: `POST /api/v1/libraries/{id}/scan`, but not at once (D-23). The job enters `scan_wait` (Queue: "Waiting for Komga", "scan in N s"). Each Komga library has one timer; a new file in the same library restarts it (hard cap 300 s). When the library is quiet, Pearlie asks for one scan, the jobs show `verifying` ("Checking Komga") while Pearlie looks for each book, and a found book ends as Done. A book not found after the tries also ends Done, with the notice "waiting for Komga". The download slot is free as soon as the file is placed. Both states count as saving for the save buttons and allow Remove only. The delay is the setting `komga_scan_wait_s` (Options > Save folders > "Komga scan delay", 0-120 s, default 10; 0 scans at once), read at each save. After a restart, waiting jobs get a fresh timer.
- Pearlie writes the CBZ itself, so it needs write access to the Komga library folder (`PEARLIE_KOMGA_INCOMING_DIR` or a per-site folder in Options > Save folders; must sit inside a Komga library root). Pages are built under `PEARLIE_KOMGA_TEMP_DIR` (same volume, `.part` then rename) and stale work folders are removed at startup. The CBZ is byte-for-byte repeatable, so its MD5 identifies it; a name clash gets `_2`, and a failed scan is a `scan_failed` notice (Komga scans later).
- Placement (D-22, full design in `docs/design-komga-series-oneshot.md`): an nhentai save goes into a series folder `[Author] Root` or into the library's oneshots folder (name read from Komga `oneshotsDirectory`, never set in Pearlie). Options > Save folders has a two-segment switch `komga.place_mode`: `auto` (Pearlie decides) or `suggest` (default). In `suggest` the Save button of an nhentai item opens a sheet that loads `GET /api/save/placement?source=&post_id=`, shows "Series [Foo] Root · vol N" or "Oneshot", and offers one tap "Make oneshot" / "Make series"; the sheet always sends the confirmed kind in `POST /api/save` as `placement {kind}`; the backend joins by name prefix only for the suggestion and for a save that carries `placement`. Batch, rule and filter saves send no `placement`. Name-prefix joins ("Love Hotel Nights" into "Love") work only in `suggest`, and only through the sheet. `GET /api/destinations` carries `komga_oneshots_dir` for the read-only "Oneshots:" line in Options.
- `ComicInfo.xml` fields: `Series` (parody), `Title`, `Tags`, `Genre` (category), `Writer`/`Penciller` (artist), `LanguageISO`, `Web` (source URL). Komga imports them only if the library's metadata import settings allow ComicInfo.
- Browsing and reader: `/api/v1/series`, `/api/v1/books`, `/thumbnail`, `/api/v1/books/{id}/pages/{n}`; progress `PATCH /api/v1/books/{id}/read-progress`.
- Reader page thumbnails: `GET /api/media/komga/books/{id}/pages/{n}/thumb`, proxied from Komga's page thumbnail; the book detail carries `page_thumb_url` as a template.
- Reader chrome (toolbar, title pill, page progress) shows on open and on a real mouse move (not on touch, zero-delta or post-click synthetic moves), on keys that open UI on purpose (books, settings, help, thumbs) and when keyboard focus enters it; page turns by click, key or wheel leave it hidden; touch tap toggles it.
- Trash (T-306): Pearlie never uses Komga's own delete. It moves the file, scans, then `POST /api/v1/libraries/{id}/empty-trash`. That call purges every soft-deleted item of the library, so the guard (all soft-deleted items are ours) is a must; Pearlie lists them with `deleted=true` conditions first. A restore scans the library and looks the item up by id, then by path.
- Komga 1.30.0 (Nov 2026) replaced deprecated endpoints: check each one in `/swagger-ui.html` first.

## 8. Filters

| Layer | Content | Editable |
|---|---|---|
| Base list | minor-content tags plus site aliases | no |
| Reject | tags never shown or saved | yes |
| Warn | tags shown blurred with a label | yes |
| Require (optional) | save only if one of these is present | yes |
| Tag mapping | which tags go to Stash, which into ComicInfo fields | yes |

- Order: base list, reject, require, warn. The first match decides.
- Runs in three places: added to the site query where supported (`-tag`), on returned results (hidden posts never reach the UI, the thumbnail proxy refuses them), and at save time against the full metadata.
- Library view: matching items are hidden or blurred; a one-time report lists them. Pearlie never deletes on its own.
- Matching: lowercase, space = underscore = hyphen, optional type scope (`artist:x`), alias table across sites.
- UI: chips per list, tap a tag on any post to reject it, JSON import/export, `POST /api/rules/test` shows which rule decides.
- Engine (shipped, `backend/app/filters/rules.py`): `evaluate()` runs base list, reject, require, warn; the first match decides. `require` is global: when any require rule exists, a post must match at least one of them, else verdict `require_missing`. Rules live in the SQLite `rules` table (`list` = reject, warn, require or mapping; `enabled`; mapping rows carry `target`) with a version in `settings` key `rules.version`.
- API: `GET /api/rules`, `PUT /api/rules` (full replace; a stale `version` returns 409 `stale_version`; entries 1-64 chars else 422 `invalid`; a `base_list` key in the body is ignored, the base list is read-only), `POST /api/rules/reject` and `DELETE /api/rules/reject` (body `{tag}`; add or remove one reject entry atomically, retry on a stale version up to 3 times, then 409; returns `{added|removed, version}`; the Undo toast calls DELETE), `POST /api/rules/test` (tags, optionally `scope:name` -> decision, layer, rule, tag, alias).
- Search: each result post is evaluated; reject, base and require_missing posts are dropped and counted in the section `hidden`; warn posts are kept with `blur: {tag}`. A page can come back short (hidden posts are not refilled); `total` and `pages` come from the site. In real mode the Stash images, Stash videos and Komga books sections query the configured Stash/Komga with the raw search text (same clients and item mapping as the library routes, media through `/api/media/...`); an unconfigured service answers `not_configured`, an unreachable one a per-section `upstream_error`.
- Save: `POST /api/save` evaluates the post's full tag metadata; reject, base and require_missing refuse with 422 `rejected_by_rule` plus `layer` (`base`, `reject` or `require`), `rule`, `tag`, `alias`; warn saves. The base list is `filters/base_list.txt` (one tag per line, optional `tag: alias1, alias2`), shipped in the package, never writable through the API, fail closed at startup. Every tag scope is checked, bare and as `scope:name` (a bare rule matches any scope, `scope:name` only that scope). Normalization is `filters/aliases.fold`.
- Not yet: tag mapping is stored and edited through the API but not applied at save (no ComicInfo writer for web saves; Stash tags are saved as returned by the site); `-tag` injection into site queries.

## 9. API (first version)

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/search?q=&sources=&page=&page_size=&order=&rating=&safe=` | one search across library and sites; `safe=1|0` drops warn-blurred posts on the server (counted in `hidden`; absent: the stored sfw option; a view choice, not access control); results grouped per section; `order` newest\|score and `rating` csv g,s,q,e apply to web sites (a section `notice` says when a filter is local or dropped) |
| GET / PUT | `/api/tabs` | the global list of search tabs `{tabs: [{id, q, src, sites, order, rating}], active, rev}`; PUT must send the current `rev` or gets 409; stored in the settings table (in memory in fixture mode) |
| GET | `/api/search/filters` | per source: the order, rating, sort, per-page options the toolbar may offer; no site call |
| GET | `/api/library/stash/images` · `/videos` · `/api/library/komga/series` · `/books` | the "See all" views |
| GET / PUT | `/api/view-settings`, `/api/view-settings/{source}` | per-source grid view (`mode` grid, wall, masonry or list; `per_page`; `zoom` 1-5), stored as `view.<source>` in the settings table (in memory in fixture mode). GET fills defaults (grid, 60, 3; nhentai 25) and returns `per_page_options` and `per_page_max`; PUT answers 422 `invalid` for an unknown source, mode, zoom, or a `per_page` outside 1 to the source cap |
| GET / PUT | `/api/player-settings` | the player's Autoplay user setting, body and answer `{"autoplay": bool}`, stored as `player.autoplay` ('1' or '0') in the settings table (in memory in fixture mode). GET answers `false` until set; PUT answers 422 for a body that is not a boolean |
| GET | `/api/library/{kind}/{id}` | item details |
| PATCH | `/api/library/{kind}/{id}` | rating (1-5, null clears), favorite, tags (full list replaces); answers the updated item |
| DELETE | `/api/library/{kind}/{id}` | move to trash; returns `{token, expires_at, retention_days, item}`. Real mode, Stash images and videos only: the file is renamed into `PEARLIE_TRASH_DIR/<token>/` (same volume, never copied), then Stash drops the entry (`delete_file` false); a failed Stash call moves the file back. 404 `not_found`, 409 `already_trashed`, 422 `multi_file` / `in_archive` / `path_outside_library`, 503 `trash_unavailable` (folder missing, read-only, other volume, or inside a library), 502 `upstream_error`. Komga books and series work the same way (D-T306): the file or folder is renamed into the trash, the item is hidden at once, and Pearlie asks Komga for one debounced library scan, waits until Komga marks the item deleted, then calls `empty-trash` for that library, but only when every soft-deleted item of the library is one Pearlie trashed (checked right before the call; a foreign soft-deleted item means skip and log the count). If the scan or empty-trash fails, the item stays hidden by Pearlie and the file stays in the trash. A trashed Komga id is hidden from list and detail (404) |
| POST | `/api/trash/{token}/restore` | undo: file back to its path (a `-N` suffix if the path is taken), Stash scan, tags and metadata re-applied, `saved_items` re-pointed. 502 `restore_incomplete` if the file is back but Stash did not index it. Komga: the file goes back, Pearlie scans and finds the item (same id if empty-trash has not run, else a new id), then re-applies tags (`tagsLock`) and book read progress and re-points `saved_items` |
| POST | `/api/library/trash` | batch delete for the Library select mode. Body `{items: [{kind: image|video|series|book, id}]}`; each item goes through the same move as `DELETE /api/library/{kind}/{id}`. Returns `{group, results: [TrashResult], failed: [{kind, id, code}]}`; all items of one call share one `group` id (`group_id` on each trash record). A failed item does not stop the others |
| POST | `/api/trash/group/{group}/restore` | Undo for a batch: restores every item of the group, returns `{restored: [RestoreResult], failed: [{token, code}]}`. The Library Undo toast (8 s) calls it |
| GET | `/api/trash` | list trashed items with token, expires_at, retention_days; expired entries are left out but not dropped by the GET (they are dropped on restore, on empty, or when retention purges them) |
| DELETE | `/api/trash` | Empty: permanently delete everything in the trash, returns `{removed}` (the real deletion rule 4 allows; the UI asks to confirm first). Real mode purges every `trashed` row and its files, and the matching Komga `saved_items` rows |
| DELETE | `/api/trash/{token}` | Delete for good: one item, 204 (404 if not `trashed`) |
| GET | `/api/trash/status` | `{roots: [{index, stash_path, state}]}`, one per Stash library root; `state` is `ok`, `not_reachable` or `other_volume`. Probe: an empty `.pearlie-probe-*` file is created in the root, renamed into the trash folder and back, then removed on any outcome (never an item). Cached 60 s. Only the Stash-side path is returned, never the container path |
| GET | `/api/trash/purge-preview` | `?days=` count of items a shorter retention would purge, no change |
| GET | `/api/media/...` | proxy for thumbnails, images, video (Range), book pages |
| GET | `/api/media/web/{source}/{post_id}/thumb` | web-site tile thumbnail, cached on disk and fetched through a per-site thumbnail lane (one at a time, 0.25 s, site-wide backoff on 429/503); a hit never touches the site. `source` is one of the four web sites, `post_id` matches `[A-Za-z0-9_-]{1,32}`, else 404 |
| GET | `/api/media/web/{source}/{post_id}/{preview\|full}` | web media. | GET | `/api/media/web/nhentai/{id}/book` | book meta (title parts from `parse_title`, page count, tags), cached 10 min |

| GET / POST / DELETE | `/api/jobs`, `/api/jobs/{id}`, `/retry` | queue (newest first; `?state=` CSV; jobs carry `notices`). Every mutating `/api` route (POST, PUT, PATCH, DELETE) is refused with 403 `forbidden` unless its `Origin` (or `Referer`) matches the request host (an app-wide dependency, so later routers are covered). Connections routes, `PUT /api/update/settings` and `PUT /api/logs/settings` also require `Content-Type: application/json` (415); `POST /api/update/apply` has no body and relies on the Origin check alone; `POST /api/update/rollback` and `/restart` take a JSON body. `PEARLIE_TRUSTED_NETWORK=1` allows a non-loopback bind (Tailscale/WireGuard or a reverse proxy with login in front); without it the app refuses to start on a non-loopback host. Every `/api` route (not the static files) also checks the `Host` (or `X-Forwarded-Host`) against an allowlist, 403 `forbidden` otherwise, so DNS rebinding cannot pass the Origin check: IP literals (v4/v6, any port), `localhost`, `*.ts.net` and the names in `PEARLIE_ALLOWED_HOSTS` (comma list in `.env`; set it when you reach Pearlie through a reverse-proxy name). The rejected host is logged once per request as a warning.

PATCH per side (real mode): Stash images and videos take `rating` (stored as rating100 = rating x 20) and `tags` (names are matched case-insensitively against Stash tags, missing ones are created, then rating and tags go in ONE sceneUpdate or imageUpdate mutation, so an edit is never half applied; a tag created before a failed update stays in Stash). Komga series and books take `tags` only, written to the metadata endpoint with `tagsLock: true` so a library scan does not undo the edit; a series shows the union of its own and its books' tags, so removing a tag that a book also carries leaves it in the list. A field the side cannot store answers 422 `unsupported_field` with `field` set, checked before any upstream call (Stash: any non-null `favorite`; Komga: any non-null `favorite` or `rating`); `null` or omitted is ignored. An empty tag or one over 64 characters answers 422 `invalid_tag`; an unknown or non-numeric id 404 `not_found`; Stash or Komga failing 502 `upstream_error`. Fixture mode still accepts favorite and rating on every kind until the UI hides those controls on the sides that cannot store them. DELETE moves Stash images and videos and Komga books and series to the Pearlie trash (see the trash routes above). The Library select mode (hover or focus circle on a tile, count + Trash + X on the filter row, Esc leaves) sends one `POST /api/library/trash` and shows an 8 s Undo toast.

Paging fields: list and search answers carry `page` (the page actually served), `page_size`, `total`, `pages` (null where the source gives no count, such as Danbooru) and, for Stash, `stats {megapixels, size_bytes}`. `page_size` is clamped to the source cap (200 Stash, Komga, Danbooru; 100 Gelbooru, Rule34; 25 nhentai; search `page_size` above 200 is a 422). A `page` past the last one is served as the last page, never an error. With several sources in one search `page_size` is ignored (each section keeps its short preview) and the section `page_size` is null.

Auth: a login that returns a token (cookie for the web UI, bearer token for iOS).

### Thumbnail cache

A disposable cache of web-site thumbnails (Danbooru, Gelbooru, Rule34, nhentai). Thumbnails only: never full images, video, book pages or nhentai page images; Stash and Komga thumbnails are not cached. Code: `backend/app/thumbcache.py`.

- **Root:** `PEARLIE_THUMB_CACHE_DIR`, default `thumbcache` next to the database (`data/thumbcache`). A root inside the trash folder, `stash_temp_dir` or `komga_temp_dir` is refused.
- **Layout:** one folder per site (fixed list of four ids), file name `sha256(source + "\0" + post_id)` in hex with a two-character fan-out folder and the extension `.img`. The name holds no URL, token or cookie. The content type is read from the first bytes at serve time.
- **Write:** atomic (`*.part` in the same folder, then `os.replace`); start-up deletes leftover `*.part`.
- **Cap:** `thumbcache.max_mb` in the settings table, default 1024, allowed 50 to 20480. Eviction is by least recent use: a hit touches the file's mtime. The folder is the truth; no index. A background walk at start-up builds the in-memory total. After a store above the cap, the oldest files go until the total is at most 90 % of the cap. Lowering the cap evicts at once.
- **Errors:** a full disk or write error serves the bytes without storing them and logs one warning a minute. A folder that is missing or not writable at start-up runs the cache in pass-through mode (fetch and serve, no store) and Options shows "cache unavailable".
